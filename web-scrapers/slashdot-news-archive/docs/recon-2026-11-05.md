# Recon: slashdot.org homepage firehose — 2026-11-05

Investigation for `../scraper.py` (Phase 1 of scraper-development-skill, Playwright MCP +
curl replay).

## 1. Target request

Plain `GET https://slashdot.org/?page=N` (N omitted/0 = homepage) returns the complete
page as static HTML. Verified with both Playwright and `curl` (HTTP 200, ~135 KB,
full `<article>` markup present) — **no JS execution required** for the story data.

## 2. requests replay

Confirmed: `curl -A <browser UA>` and even curl's default UA get HTTP 200 with all
`data-fhtype="story"` articles. No cookies needed, no 401/403. → **static-html
strategy (requests + BeautifulSoup)**; no browser in the recurring job.

## 3. Selectors

Per story, `article.fhitem-story` (`data-fhid` = firehose id, `data-fhtype="story"`):

| Field | Selector |
|---|---|
| firehose id | `article[data-fhid]` |
| title + story URL | `.story-title a` (href `//<section>.slashdot.org/story/YY/MM/DD/HHMMSS/slug`) |
| external source | `.story-sourcelnk` ("(domain.com)", href = source article) |
| comment count | `.comment-bubble a` |
| author | `.story-byline a` |
| displayed time | `.story-byline time` (human text; authoritative time is in the story URL) |
| dept | `.dept-text` |
| topic | `.topic a` href `index2.pl?fhfilter=<topic>` |
| full post text | `div.body` (id `fhbody-<fhid>`, inner `div#text-<fhid>.p`) |

Homepage (`?page=0`) carries 15 story articles plus ~10 non-story articles (ads,
polls) which are filtered out by `data-fhtype="story"`.

## 4. Pagination

`?page=N`, ~15 stories/page, distinct per page (no overlap). `« Newer` / `Older »` links.
Probed depth: page=5000 still returns stories (reaches 2016-02); pagination is
effectively unbounded for the archive. Gap-fill = walk N=1,2,… until a page has only
already-known stories.

## 5. Auth / bot detection

None on plain GET. The browser page fires Cloudflare `cdn-cgi/challenge-platform`
requests and `/svc/z/` tracking (403s) — all ignorable; the HTML document itself is
served cleanly to plain HTTP clients.

## 6. robots.txt

`/` and `/?page=N` allowed. Disallowed and never fetched: `/stories/…`,
`/comments.pl`, `/search`, etc. The full post text is on the listing page, so the
disallowed story pages are not needed.

## 7. Timestamps

The numeric segment in the story URL (`/story/26/11/05/0322258/…`) is Slashdot's
*submission* time in an ambiguous variable-width encoding (6–7 digits; e.g. `207222`
does not parse as HHMMSS) and does NOT match publish times — do not use it.

The publish time is the displayed byline (`<time datetime="on Wednesday November 04,
2026 @10:30PM">`), rendered in the viewer's tz; the anonymous default is
**America/New_York**. Verified 2026-11-05: parsing the byline as America/New_York and
converting to UTC reproduces the `slashdot.xml` backslash feed's UTC `<time>` exactly
for all 15 homepage stories (15/15). The scraper therefore stores `posted_at` = byline
→ UTC, and keeps the raw displayed text in `byline_time`.

## 8. Volume budget

- Daily incremental run: 1 + up to `--max-pages` (default 10) requests; typically 1–3
  once caught up. Recurring but far below the 10k+ band → home egress fine.
- One-time `backfill --max-pages 5000`: ~5000 one-shot requests ("low thousands" band,
  stated to user; home egress acceptable). All paced via request-auth permits, and
  repeat pages are served from webcache, so a re-run of backfill costs ~0 target
  requests.
- Render path: none (static HTML). No images fetched.
